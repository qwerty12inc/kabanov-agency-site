# kabanov.agency — автономная статическая копия

Полная копия сайта, снятая с Framer. Работает без подписки Framer: весь JS, шрифты,
картинки и данные CMS лежат рядом. Единственные обращения наружу — плееры Vimeo
на 26 страницах, оставленные намеренно (см. раздел ниже).

```
site/            готовая статика — это и есть сайт
  index.html          RU-главная
  en/index.html       EN-главная
  projects/…          31 проект × 2 локали
  categories/…        7 категорий × 2 локали
  404.html            страница 404
  assets/             226 файлов, 77 МБ
    js/               45 JS-чанков Framer
    modules/          6 модулей CMS
    cms/              6 файлов данных CMS (.framercms)
    fonts/            23 шрифта (Google Fonts + Fontshare, самохостинг)
    images/           140 картинок, включая варианты для srcset
    media/, data/, vendor/
  sitemap.xml, sitemap_ru.xml, sitemap_en.xml, robots.txt
tools/           скрипты снятия копии и проверок
deploy/          конфиги nginx и Caddy
```

## Быстрый старт

```bash
npm install
npm run serve         # http://127.0.0.1:4173
```

## Пересборка копии с живого сайта

Пока оригинал ещё доступен, копию можно пересобрать целиком:

```bash
npm run crawl     # sitemap → скачивание всех страниц + краулинг ссылок
npm run assets    # сбор внешних ресурсов в /assets и переписывание путей
```

`crawl` кладёт сырые страницы в `.work/pages`, `assets` собирает из них `site/`.
`.work/` в git не попадает.

## Проверки

```bash
npm run check:links   # все ссылки /assets/… указывают на существующие файлы
npm run check:seo     # hreflang/canonical/og не изменились относительно оригинала
npm run audit         # Playwright: обход всех страниц, лог сетевых запросов
npm run shots         # скриншоты локально и с живого сайта, попиксельное сравнение
```

`audit` и `shots` требуют запущенного `npm run serve` в соседнем терминале. Оба
прогона возобновляемые: результат каждой страницы дописывается в `.work/*.jsonl`,
и повторный запуск продолжает с места остановки.

## Что изменено относительно оригинала

Переписаны на локальные пути (`/assets/…`) все ресурсы с `framerusercontent.com`,
`fonts.gstatic.com` и `unpkg.com`. Пути сделаны абсолютными от корня сайта, а не
вида `../../assets/…`: Framer — SPA, после навигации через pushState базовый URL
документа меняется, и относительный путь, вставленный React'ом уже после перехода,
разрешился бы неправильно.

**Вырезано** (по одному экземпляру на каждой из 83 страниц):

| Что | Зачем |
|---|---|
| `events.framer.com/script` | телеметрия Framer, без подписки бесполезна |
| `googletagmanager.com/gtag/js` + инлайн-бутстрап | Google Analytics, внешний запрос |
| GTM-контейнер `GTM-NCWVTW4B` | то же |
| хук панели редактирования Framer | тянул `framer.com/edit/init.mjs` |
| `preconnect` на `fonts.gstatic.com` | шрифты теперь локальные |

Ваш собственный скрипт трекинга кликов по контактам (`click_lets_talk`) **оставлен
без изменений**. Он проверяет наличие `gtag`/`dataLayer` и при отключённой аналитике
просто ничего не делает — вернёте аналитику, и он заработает снова.

**Точечные правки внутри JS-чанков** (иначе копия не работает):

- `new URL("./x", "https://framerusercontent.com/…/y.js")` — база после
  переписывания становилась относительной, а конструктор `URL` требует абсолютную
  и падал с `Invalid base URL`, роняя гидратацию страницы целиком. База достраивается
  через `location.origin`.
- Строки `https://fonts.gstatic.com/s/` и `…/third-party-assets/fontshare/` — это не
  адреса загрузки, а префиксы для `startsWith()`, которыми рантайм определяет
  источник шрифта. Заменены на `/assets/fonts/gstatic-` и `/assets/fonts/fontshare-`;
  схема имён файлов подобрана так, что классификация осталась прежней.
- Динамический `import()` панели редактирования заменён на локальную заглушку.

**SEO не тронут.** Все 1162 тега `canonical`, `hreflang` (ru / en / x-default),
`og:*` и `twitter:*` на 83 страницах сохранены байт-в-байт, с абсолютными URL на
`kabanov.agency`.

## Деплой на российский хостинг

Подходит любой VPS: Timeweb, Selectel, reg.ru, Yandex Cloud.

```bash
npm run precompress                      # готовит .gz и .br
rsync -av --delete site/ user@host:/var/www/kabanov.agency/
```

Конфиг: `deploy/nginx.conf` либо `deploy/Caddyfile` (Caddy сам получает и продлевает
сертификат Let's Encrypt — с российского IP он доступен).

Оба конфига приводят URL к тому же каноничному виду, который прописан в тегах
`canonical` от Framer:

- `/` и `/en/` — **со** слэшем на конце;
- `/projects`, `/categories/ui`, `/projects/w24` — **без** слэша.

Это важно: если отдавать страницу и со слэшем, и без, поисковики увидят дубли.
Штатный `try_files $uri $uri/` для этого не годится — nginx сам сделает 301 на слэш
и сломает канонизацию, поэтому в конфиге путь к `index.html` указан явно.

### Что сделано для доступности из России

- Шрифты Google и Fontshare перенесены на свой домен — `fonts.gstatic.com` из РФ
  отвечает нестабильно, теперь он не нужен вовсе.
- Убран `unpkg.com` (CSS библиотеки Lenis) — CDN за Cloudflare.
- Убраны Google Analytics и GTM — внешние запросы к инфраструктуре Google.
- Нет ни одного обращения к `framerusercontent.com` в рантайме.

Итог: для отрисовки странице нужен только ваш сервер. Единственное исключение —
плееры Vimeo, см. ниже.

### Плееры Vimeo — осознанно оставлены

На 26 страницах из 83 стоят видео Vimeo (25 разных роликов). Решено сохранить их
в исходном виде, поэтому эти страницы при просмотре обращаются к `vimeo.com`,
`player.vimeo.com`, `f.vimeocdn.com`, `i.vimeocdn.com` и `arclight.vimeo.com`.
Это единственные внешние запросы во всей копии; `npm run audit` показывает их
отдельной строкой как разрешённое исключение и падает, если появится что-то ещё.

Два следствия, о которых стоит помнить:

- **Vimeo заблокирован в России** — у российских посетителей видео не проиграется.
  На остальных странице это не сказывается: плеер отваливается изолированно.
- **Два ролика уже отдают 401** (`1071490791` и `1071490853`) — это не следствие
  копирования, на живом сайте они сломаны точно так же. Стоит проверить их
  настройки приватности в аккаунте Vimeo.

Если когда-нибудь понадобится полная автономия, видео придётся выгрузить из
своего аккаунта Vimeo (снаружи эндпоинт плеера закрыт, отдаёт 403) и заменить
плееры на теги `<video>`.

### Что стоит решить отдельно

1. **`og:image` ведёт на `framerusercontent.com`.** Теги Open Graph оставлены без
   изменений, как и требовалось. Но когда подписка Framer кончится, картинки превью
   в мессенджерах и соцсетях перестанут открываться. Файлы уже скачаны локально —
   чтобы переключить теги на свой домен:
   ```bash
   OG_LOCAL=1 npm run assets
   ```
   `og:image` станет `https://kabanov.agency/assets/images/…`, остальные теги не
   изменятся.

2. **Аналитика отключена.** Если нужна — верните GA или поставьте что-то, что не
   ходит наружу из РФ: Яндекс.Метрика либо self-hosted Umami/Plausible на том же
   сервере. Ваш скрипт `click_lets_talk` подхватится автоматически, если вернёте
   `gtag` или `dataLayer`.

3. **Переключателя языков на сайте нет.** Проверено на живом сайте: ни на одной
   странице, ни на одном брейкпоинте нет ссылки между RU и EN, автоопределения языка
   по браузеру тоже нет. Локали связаны только тегами `hreflang` и достижимы по
   прямому URL. Если переключатель нужен — это отдельная задача, он добавит новый
   элемент в вёрстку.

4. **Домен `.agency` у зарубежного регистратора.** Сам сайт после переезда ни от чего
   зарубежного не зависит, но продление домена — да. Если это риск, стоит завести
   зеркало на `.ru`.
