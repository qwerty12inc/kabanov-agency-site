# Переключение DNS в GoDaddy — инструкция для расширения Claude для Chrome

Соответствует шагу **⛔ СТОП 1** из `DEPLOY.md`. Выполняется вручную, потому что
DNS домена обслуживается у стороннего регистратора.

## Что известно на момент написания

Терминальный агент снял текущее состояние:

| Имя | Сейчас |
|---|---|
| `kabanov.agency` | две записи A: `31.43.161.6` и `31.43.160.6` |
| `www.kabanov.agency` | **CNAME** на `sites.framer.app.` |

Нужно получить обе записи типа A на `158.160.179.74`.

Главный подвох в `www`: там **CNAME, а не A**. Для одного имени эти типы
сосуществовать не могут, поэтому CNAME придётся удалить и создать A — это не
правка значения.

## Промпт

Скопировать целиком в расширение при открытой панели GoDaddy.

```
Ты работаешь в панели GoDaddy в моём реальном аккаунте. Домен kabanov.agency
обслуживается здесь. Задача — переключить его на новый сервер 158.160.179.74.

ЖЁСТКИЕ ОГРАНИЧЕНИЯ, соблюдай буквально:
- Меняй ТОЛЬКО записи для имён «@» (сам kabanov.agency) и «www».
- НЕ ТРОГАЙ записи MX, TXT, SPF, DKIM, DMARC, NS, SRV. На них держится
  почта и подтверждение владения доменом; их изменение оставит нас без
  входящих писем.
- Ничего не удаляй, кроме прямо указанного ниже.
- Перед сохранением ОСТАНОВИСЬ, покажи таблицу «было → станет» и дождись
  моего явного «да».
- Не заходи в разделы оплаты, не меняй настройки аккаунта и владения доменом.
- Если интерфейс отличается от описания — не подбирай замену сам, опиши что
  видишь и спроси.

ШАГ 1 — снять текущее состояние, ничего не меняя.

Открой управление DNS для kabanov.agency и выпиши мне ВСЕ записи целиком:
тип, имя, значение, TTL. Это точка отката, она нужна до любых правок.

Отдельно ответь на три вопроса:
  а) есть ли запись типа CAA и что в ней указано;
  б) какой TTL у текущих записей A и CNAME;
  в) включена ли переадресация домена (Domain Forwarding) — она может
     перекрывать записи.

ШАГ 2 — план изменений. Покажи его таблицей и жди подтверждения.

Должно получиться:
  @     A   158.160.179.74   TTL 600
  www   A   158.160.179.74   TTL 600

Из этого следует:
  - у «@» сейчас ДВЕ записи A (31.43.161.6 и 31.43.160.6) — обе заменяются
    одной; лишнюю удалить, оставшуюся отредактировать;
  - у «www» сейчас CNAME на sites.framer.app — его нужно УДАЛИТЬ и создать
    вместо него запись A. CNAME и A для одного имени сосуществовать не могут.

TTL 600 секунд выбран намеренно: если понадобится откат, он подействует за
десять минут, а не за час.

ШАГ 3 — применить, только после моего «да».

ШАГ 4 — перечитать записи в панели и показать мне итог. Убедись, что:
  - для «@» осталась ровно одна запись A со значением 158.160.179.74;
  - для «www» есть запись A со значением 158.160.179.74 и нет CNAME;
  - записи MX и TXT остались ровно такими же, как ты выписал на шаге 1.

Распространение записей проверю я снаружи, из панели этого не видно.
```

## После применения

Дождаться распространения (проверяет терминальный агент):

```bash
dig +short kabanov.agency         # 158.160.179.74
dig +short www.kabanov.agency     # 158.160.179.74
```

Пока оба имени не вернут новый адрес, к выпуску сертификата не переходить.

## Откат

Вернуть записи из выписки шага 1: для «@» две записи A на `31.43.161.6` и
`31.43.160.6`, для «www» CNAME на `sites.framer.app`. Работает, пока подписка
Framer активна — не отключайте её до конца проверки на шаге 6 `DEPLOY.md`.

## Почему спрашиваем про CAA

Запись CAA ограничивает, какой удостоверяющий центр вправе выпускать
сертификаты для домена. Если она есть и не разрешает `letsencrypt.org`, certbot
на шаге ⛔ СТОП 2 получит отказ. Узнать это лучше сейчас, чем потратить попытку
у Let's Encrypt.
