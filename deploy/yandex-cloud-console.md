# Инструкции для расширения Claude для Chrome — консоль Yandex Cloud

Браузерная часть развёртывания. Всё, что делается по SSH (nginx, сертификат,
заливка файлов), сюда не входит — расширение работает только с консолью.

Порядок такой:

1. **Этап 1** — создать виртуальную машину. Промпт ниже.
2. **Этап 2** — настроить сервер по SSH и залить сайт. Это терминал, см. `README.md`.
3. **Этап 3** — подключить CDN. Промпт ниже, но **только после того**, как сайт
   уже открывается по домену: CDN настраивается поверх работающего источника.

Параметры машины взяты из замеров: сайт занимает 98 МБ, страница весит около
0,9 МБ, процессор при раздаче статики простаивает.

---

## Этап 1. Создание виртуальной машины

Скопируйте всё, что ниже, в расширение при открытой консоли Yandex Cloud.

```
Ты работаешь в консоли Yandex Cloud в моём реальном аккаунте с подключённым
биллингом. Задача — создать одну виртуальную машину под статический сайт.

ЖЁСТКИЕ ОГРАНИЧЕНИЯ, соблюдай их буквально:
- Не удаляй и не изменяй никакие существующие ресурсы. Только создание нового.
- Не создавай сервисные аккаунты, не выпускай API-ключи и статические ключи
  доступа, не меняй права IAM.
- Не открывай разделы с платёжными данными и не меняй настройки биллинга.
- Никуда не копируй и не показывай в чате токены, ключи и пароли.
- Перед финальной кнопкой «Создать виртуальную машину» ОСТАНОВИСЬ, покажи мне
  сводку параметров и итоговую стоимость и дождись моего явного «да».
- Если какое-то поле называется в интерфейсе иначе, чем у меня, или значения
  недоступны — не подбирай замену сам, опиши что видишь и спроси.

ШАГ 1. Открой сервис Compute Cloud в нужном каталоге и нажми
«Создать виртуальную машину». Если каталогов несколько — сначала покажи мне
список и спроси, в каком создавать.

ШАГ 2. Заполни поля:

Блок «Общая информация»
  Имя: kabanov-agency-web

Блок «Образ загрузочного диска»
  Ubuntu 24.04 LTS
  ВАЖНО: именно 24.04, не 26.04 и не другую версию. Конфигурация сервера
  проверена на nginx из 24.04, на других версиях поведение не проверялось.

Блок «Расположение»
  Любая зона доступности, запомни какую выбрал.

Блок «Диски и файловые хранилища»
  Тип: SSD
  Размер: 15 ГБ

Блок «Вычислительные ресурсы»
  vCPU: 2
  Гарантированная доля vCPU: 20%
  RAM: 2 ГБ
  «Сделать ВМ прерываемой»: ВЫКЛЮЧЕНО.
  Это критично: прерываемая машина останавливается автоматически, и сайт
  ляжет. Если галочка включена по умолчанию — сними её.

Блок «Сетевые настройки»
  Подсеть: существующая в выбранной зоне. Если сети нет вообще — остановись
  и скажи мне, не создавай ничего молча.
  Публичный IP-адрес: «Автоматически»
  Группа безопасности: нужна такая, где разрешены входящие подключения на
  порты 80 (HTTP), 443 (HTTPS) и 22 (SSH), и разрешён весь исходящий трафик.
  Если подходящей группы нет — покажи мне, какие есть, и предложи создать
  новую с этими правилами, но не создавай без моего подтверждения.

Блок «Доступ»
  Логин: deploy
  SSH-ключ: ОСТАНОВИСЬ и попроси у меня публичный ключ. Сам ключ не
  генерируй и ниоткуда не подставляй.

ШАГ 3. Покажи сводку и стоимость, дождись подтверждения, только потом создавай.

ШАГ 4. После создания:
  а) Дождись статуса RUNNING.
  б) Зайди в VPC → «IP-адреса», найди публичный адрес этой машины и сделай
     его статическим. Это обязательно: динамический адрес меняется при
     остановке машины, и DNS-запись домена перестанет работать.
  в) Сообщи мне: публичный IP, имя машины, зону доступности и внутренний
     адрес. Больше ничего из консоли выписывать не нужно.
```

После этого настройка идёт по SSH — см. раздел «Деплой» в `README.md`.
A-запись домена `kabanov.agency` направьте на полученный статический IP
у текущего DNS-провайдера домена.

## Этап 3. Подключение CDN

Запускать **только после** того, как сайт открывается по `https://kabanov.agency`
напрямую с сервера. CDN кэширует то, что отдаёт источник; если источник ещё не
готов, в кэш попадут ошибки.

```
Ты работаешь в консоли Yandex Cloud в моём реальном аккаунте с подключённым
биллингом. Задача — поставить CDN перед уже работающим сайтом
https://kabanov.agency

Те же жёсткие ограничения, что и раньше: ничего не удалять и не изменять из
существующего, не трогать IAM и биллинг, не показывать в чате секреты, перед
любым созданием платного ресурса показать сводку и стоимость и дождаться
моего «да».

ШАГ 1. Открой сервис Cloud CDN. Если он не активирован — покажи, что просят
для активации, и спроси.

ШАГ 2. Создай группу источников (origin group):
  Источник: IP-адрес сервера, который я тебе дам.
  Протокол до источника: HTTP.

ШАГ 3. Создай CDN-ресурс:
  Доменное имя для раздачи: kabanov.agency
  Группа источников: созданная на шаге 2.
  Протокол с клиентами: HTTPS, с редиректом с HTTP на HTTPS.
  Сертификат: нужен сертификат для kabanov.agency в Certificate Manager.
  Если его там нет — остановись и спроси, выпускать ли новый от Let's Encrypt.
  Кэширование: включить, время жизни брать из заголовков источника.
  Сервер уже отдаёт правильные заголовки: файлы в /assets помечены
  immutable на год, HTML — must-revalidate. Не переопределяй их своими
  значениями TTL, иначе после обновления сайта посетители получат старую
  версию.
  Сжатие на стороне CDN: НЕ включай. Файлы уже сжаты заранее, а для данных
  CMS (расширение .cmsdata) сжатие ломает загрузку — сайт теряет
  интерактивность.

ШАГ 4. Покажи сводку и стоимость, дождись подтверждения, создавай.

ШАГ 5. После создания сообщи мне CNAME-адрес, который выдал CDN, и какие
DNS-записи нужно поменять. Сами записи не меняй — домен обслуживается не здесь.
```

---

## Что расширение сделать не сможет

- Настроить nginx, получить сертификат, залить файлы — это SSH, не браузер.
- Сгенерировать SSH-ключ — он должен остаться только у вас.
- Поменять DNS-записи домена, если домен обслуживается не в Yandex Cloud.

## Почему именно такие параметры

| Параметр | Значение | Почему |
|---|---|---|
| Ubuntu 24.04 LTS | не 26.04 | конфиг проверен на nginx 1.24 из состава 24.04 |
| Диск 15 ГБ | сайт занимает 98 МБ | остальное под систему, логи и запас |
| 2 vCPU, доля 20% | минимум с запасом | раздача статики процессор не нагружает |
| Прерываемая — выкл. | обязательно | иначе машина останавливается сама |
| Статический IP | обязательно | на него смотрит A-запись домена |
